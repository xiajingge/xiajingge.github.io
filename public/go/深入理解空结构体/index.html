之前写到了关于context的内容，链接是Go并发控制：context，其中就是设计到了使用空结构体来作为key的场景，所以我开始疑惑空结构体的作用是什么，所以才有了这篇文章。

1. 什么是空结构体

空结构体，顾名思义，就是没有任何字段（Field）的结构体。它的类型表示为 struct{}，而它的实例表示为 struct{}{}。

空结构体最大的特点是不占用任何内存空间。我们可以通过 unsafe.Sizeof 来验证这一点：

package main

import (
	"fmt"
	"unsafe"
)

func main() {
    type Empty struct{}

    var s1 struct{}
    s2 := Empty{}
    s3 := struct{}{}

    fmt.Printf("s1 addr: %p, size: %d\n", &s1, unsafe.Sizeof(s1))
    fmt.Printf("s2 addr: %p, size: %d\n", &s2, unsafe.Sizeof(s2))
    fmt.Printf("s3 addr: %p, size: %d\n", &s3, unsafe.Sizeof(s3))
    fmt.Printf("s1 == s2 == s3: %t\n", s1 == s2 && s2 == s3)

    // 输出：
    // s1 addr: 0x1044ef4a0, size: 0
    // s2 addr: 0x1044ef4a0, size: 0
    // s3 addr: 0x1044ef4a0, size: 0
    // s1 == s2 == s3: true
}

根据输出结果可知：

  • 多个空结构体内存地址相同。
  • 空结构体占用字节数为 0，即不占用内存空间。
  • 多个空结构体值相等。

第一个结论有点反直觉，第二个和第三个倒是很容易理解，那么就再来验证一下第一个结论。

// &c(0x5a4c40) == &d(0x5a4c40): true

那为什么 &a 与 &b 打印的地址相同？ &a == &b 和 x == y 却是 false？

a 和 b 都是大小为 0 的 struct{}。Go 运行时中有一个全局符号 runtime.zerobase，所有大小为零的变量取地址时，都会返回这个固定地址（以节省内存）。 println 不引起变量逃逸，&a 和 &b 的值在运行时都是 zerobase 的地址，所以打印结果一致。

而Go 语言规范规定：指向不同零尺寸变量的指针可能相等，也可能不相等（Pointers to distinct zero-size variables may or may not be equal）。这给了编译器自由选择的余地。

在没有逃逸的情况下，编译器可以静态分析出 &a 和 &b 来自两个不同的包级变量。为了保持“不同变量应该有不同的地址”这一直觉，编译器会直接在编译期将比较结果折叠为 false，而不是真的去比较两个 zerobase 指针的数值。

x := &a; y := &b 同理，编译器能追踪到 x 和 y 分别指向 a 和 b，且它们没有逃逸，因此 x == y 也在编译期被优化为 false。 所以尽管打印的地址相同，两个比较的结果都是 false。

因为底层存在 zerobase 这种“零大小变量共享地址”的优化机制，导致了零大小变量的指针比较是不可靠的。这就倒逼着所有 Go 开发者：在使用空结构体作为 Context Key 时，必须使用“值传递”，严禁使用“指针传递”。

为什么 &c == &d 却是 true？

注意 c 和 d 的逃逸分析输出：

1
2
3

moved to heap: c
moved to heap: d
&c == &d escapes to heap

fmt.Printf 会将参数中的指针传递给堆，导致 c、d 以及表达式 &c == &d 全部逃逸到堆上。

一旦变量逃逸，编译器就不再对其进行静态“不同变量”的优化。此时：

c 和 d 在堆上分配，但大小为零，运行时仍会返回同一个 zerobase 地址（你看到的 0x5a4c40 就是这个共享地址）。

&c == &d 成为运行时实际执行的指针比较，两个指针的值确实相同，因此结果为 true。

2.1 context中key冲突

key冲突问题

Context 的 key 可以是任意类型，那么固然也可以是任意值。我们在写代码的时候，经常会用一些如 i、info、data 等作为变量，那么我们也很有可能使用 data 这样类似的字符串值作为 Context 的 key：

package main

import (
	"context"
	"fmt"
)

const dataKey = "data"

func main() {
	ctx := context.Background()

	ctx = context.WithValue(ctx, dataKey, "some data")

	fmt.Printf("data: %s\n", ctx.Value(dataKey))

	userDataKey := "data" // 与 dataKey 值相同
	ctx = context.WithValue(ctx, userDataKey, "user data")

    fmt.Printf("user data: %s\n", ctx.Value(userDataKey))

    // 再次查看 dataKey 的值
	fmt.Printf("data: %s\n", ctx.Value(dataKey))
}

// 输出：
// data: some data
// user data: user data
// data: user data

结果很明显，虽然 dataKey 和 userDataKey 这两个 key 的变量名不一样，但是它们的值同为 data，最终导致 ctx.Value(dataKey) 返回的结果与 ctx.Value(userDataKey) 返回结果相同。

即 dataKey 的值已经被 userDataKey 所覆盖。所以我才说，通过 Context 传值并不都是“安全”的，因为你的键值对可能会被覆盖。

package main

import (
	"context"
	"fmt"
)

type dataKey struct{}
type userDataKey struct{}

func main() {
	ctx := context.Background()

	ctx = context.WithValue(ctx, dataKey{}, "some data")

	fmt.Printf("data: %s\n", ctx.Value(dataKey{}))

	ctx = context.WithValue(ctx, userDataKey{}, "user data")

    fmt.Printf("user data: %s\n", ctx.Value(userDataKey{}))

    // 再次查看 dataKey 的值
	fmt.Printf("data: %s\n", ctx.Value(dataKey{}))

// 输出：
// data: some data
// user data: user data
// data: some data
}

注意，这里基于空结构体定义一个新的类型。我们使用这个新类型的实例对象作为 key，而不是直接使用空结构体变量作为 key，这二者是有本质区别的。dataKey 和 userDataKey 一定不相等,因为它们是不同的类型.

2.2 实现集合（Set）数据结构

Go 语言的标准库中并没有内置 Set（集合）这种数据结构。在实际开发中，我们通常使用 map 来模拟 Set。

如果你使用 map[string]bool，每个键值对中的 bool 值会占用 1 个字节的内存。当你需要存储海量数据时，这 1 个字节的累积也会造成可观的内存浪费。此时，struct{} 就成了完美的替代品，因为空结构体可以仅表达语义，而不需要承载数据。

// 使用泛型实现一个现代的 Go Set
type Set[T comparable] map[T]struct{}

func (s Set[T]) Add(val T) {
	s[val] = struct{}{} // 赋值一个空结构体实例
}

func (s Set[T]) Contains(val T) bool {
	_, ok := s[val]
	return ok
}

func main() {
	mySet := make(Set[string])
	mySet.Add("apple")
	mySet.Add("banana")
	
	fmt.Println(mySet.Contains("apple"))  // true
	fmt.Println(mySet.Contains("orange")) // false
}

优势：

  • 极致省内存： Value 部分不占用任何内存。

  • 语义清晰： struct{} 明确告诉阅读代码的人：“我不关心 Value 是什么，我只关心 Key 是否存在”。

2.3 无数据传递的 Channel 信号控制

在并发编程中，Channel 经常被用于协程之间的通信。有时候，我们发送信号仅仅是为了通知某个事件的发生（例如任务完成、退出程序），而不需要传递任何实际的数据。

package main

import (
	"fmt"
	"time"
)

func worker(done chan struct{}) {
	fmt.Println("正在执行耗时任务...")
	time.Sleep(2 * time.Second)
	fmt.Println("任务完成！")
	
	// 发送一个空结构体作为完成信号
	done <- struct{}{}
}

func main() {
	done := make(chan struct{})
	
	go worker(done)
	
	// 主协程阻塞等待信号
	<-done 
	fmt.Println("主协程收到信号，准备退出。")
}

优势：

  • 相比于使用 chan bool 或 chan int，chan struct{} 在语义上更加纯粹，它就是一个“事件触发器”。

package main

import "fmt"

// 定义一个动物接口
type Animal interface {
	Speak()
}

// 定义一个空结构体
type Dog struct{}

// 为空结构体绑定方法
func (d Dog) Speak() {
	fmt.Println("Woof!")
}

func main() {
	var a Animal = Dog{}
	a.Speak() // 输出: Woof!
}

优势：

  • 无需分配多余的内存来存储无用的状态字段，代码干净利落。

package main

import "fmt"

// 定义一个泛型事件结构体
type Event[T any] struct {
	Name    string
	Payload T // 负载数据
}

// 定义一个特定的无负载事件类型：缓存清空
// 这里用空结构体作为占位符，明确表示“该事件没有携带任何数据”
type CacheCleared struct{} 

func main() {
	// 1. 带有实际负载的事件 (例如：用户登录，Payload 是用户名)
	loginEvent := Event[string]{
		Name:    "UserLogin",
		Payload: "admin_user",
	}
	fmt.Printf("事件: %s, 负载: %s\n", loginEvent.Name, loginEvent.Payload)

	// 2. 无负载的通知事件 (使用空结构体占位)
	clearEvent := Event[CacheCleared]{
		Name:    "CacheCleared",
		Payload: struct{}{}, // 赋予一个空结构体实例
	}
	
	fmt.Printf("事件: %s, 负载大小: %d 字节\n", clearEvent.Name, 0)
	
	// 在事件分发器（Dispatcher）中，可以通过反射或类型断言，
	// 优雅地识别出哪些事件是不需要解析 Payload 的纯通知事件。
}

package main

import "fmt"

// 1. 定义两个空结构体，仅作为“状态标记”的类型
// 它们不包含任何数据，大小为 0
type Raw struct{}
type Sanitized struct{}

// 2. 定义泛型结构体 FormData
// T 就是我们的“占位符”类型参数。
// 我们使用 `_ T` (空白字段) 来让编译器识别 T，但运行时它不占用任何空间！
type FormData[T any] struct {
	Content string
	_       T // 幽灵字段：仅参与编译期类型推导，运行时大小为 0
}

// 3. 业务逻辑：接收原始数据
func NewRawData(input string) FormData[Raw] {
	return FormData[Raw]{
		Content: input,
	}
}

// 4. 业务逻辑：清洗数据，并转换类型状态
// 注意：入参必须是 Raw 状态，返回值变成了 Sanitized 状态
func SanitizeData(data FormData[Raw]) FormData[Sanitized] {
	// 模拟清洗逻辑...
	cleanContent := data.Content + " [已安全过滤]"
	return FormData[Sanitized]{
		Content: cleanContent,
	}
}

// 5. 核心约束：只有 Sanitized 状态的数据才能存入数据库
// 如果传入 Raw 状态的数据，代码根本无法通过编译！
func SaveToDB(data FormData[Sanitized]) {
	fmt.Printf("成功将安全数据存入数据库: %s\n", data.Content)
}

func main() {
	// 获取未验证的数据
	rawData := NewRawData("<script>alert('xss')</script>")

	// 编译报错！
	// cannot use rawData (variable of type FormData[Raw]) as type FormData[Sanitized] in argument to SaveToDB
	// SaveToDB(rawData) 

	// 必须先经过清洗，转换状态
	safeData := SanitizeData(rawData)

	// 编译通过
	SaveToDB(safeData)
}
